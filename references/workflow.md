# 调研与验收

按“角色在条件下完成目标”拆任务，列入口、依赖、操作、状态、用户决策和终点。先正常路径，再挑影响任务结果的必填校验、权限、运行失败及恢复；不以按钮颜色、所有视口、穷举参数或重复外壳控件阻塞首版交付。

从观察记录整理模块图：入口 → 操作/条件 → 成功或阻塞；重要分支保留恢复和证据引用。跨模块图以用户任务关系为主，对未验证连接标注。预测箭头不能写成实测。

识别同一模块的不同资源来源或角色（例如自建、组织授权、平台内置），分别核对列表、详情和适用操作；不要从一种来源的空列表推断其他来源为空。检查列表加载完成后的状态，加载中、旧数据和最终空列表分开记录。离开表单前记录取消或返回后的结果，不把未提交误写成创建失败。

对下载、异步任务、外部跳转等操作，将点击、页面反馈、浏览器/服务端完成与产物可用分别记录：例如只观察页面无变化时，写明观察窗口及未检查的下载渠道，结果未知。用户目标需要的最终状态缺证时，不因入口和点击已验证而判为完成。

验收：已发现主要任务的入口、前提、操作、终点和关键错误/恢复有实证或明确未验/受阻。看到中间提示不等于最终结果；独立原始证据缺失要注明。声明身份、环境、时间、样本范围；阻塞不影响其他路径时继续无依赖工作。

任务和 Mermaid 适合建立首版。只有有收益时才建立状态机、表单/API 模型、AX/DOM 矩阵、自动化检查或录制回放。检查器验证输入模型，不能证明录入所有真实路径；回放前核对副作用。每次结论变更核对任务记录、图与证据一致性。仅在分母可信时计算覆盖率。
